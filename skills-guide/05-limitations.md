# Claude Skills 创建指南 - 限制与注意事项

---

## 一、Skill 触发机制

### 触发原理

Claude 通过评估 **Skill 描述** 与用户请求的**语义相关性**来决定是否激活 Skill。

- **不是**关键词匹配
- **是**语义关系理解

### 影响因素

| 因素 | 影响 |
|------|------|
| **模糊描述** | 降低触发准确性 |
| **过于宽泛** | 导致不适当的激活 |
| **缺失用例** | 导致遗漏激活 |

### 多 Skill 同时激活

多个 Skill 可以同时激活，如果它们处理复杂任务的不同方面。

**示例：**
- 任务：分析财务报告并生成 PDF
- 可能激活：财务分析 Skill + PDF 生成 Skill

## 二、文件大小限制

### 上下文窗口管理

编写 Skill 时，避免用不必要的内容膨胀上下文窗口。

### 关键问题

> 每条信息是否每次都需要加载，还是只在特定条件下需要？

### 推荐方案："菜单"方法

```
SKILL.md（菜单）
  ├── 描述可用选项
  ├── 使用相对路径引用详细文件
  └── Claude 按需读取
```

**原则：**
- 内容分块
- 按需加载
- 无关文件不触碰

## 三、常见陷阱

### 陷阱一：描述过于宽泛

```
❌ "This skill helps with documents."
✅ "Comprehensive PDF manipulation toolkit for extracting text 
    and tables, creating new PDFs, merging/splitting documents..."
```

### 陷阱二：缺少边界说明

```
❌ 没有说明不适用场景
✅ "Not for simple PDF viewing or basic conversions."
```

### 陷阱三：指令过于复杂

```
❌ 一个巨大的指令块
✅ 分阶段、有明确输入输出的结构化指令
```

### 陷阱四：忽视测试

```
❌ 直接部署
✅ 正常操作 + 边界情况 + 越界请求 三重测试
```

## 四、平台特定限制

### Claude.ai 限制

- 需要 Pro、Max、Team 或 Enterprise 计划
- 需要启用代码执行
- Skill 为个人级别，不组织共享
- 管理员无法集中管理

### Claude Code 限制

- 需要 `skills/` 目录结构
- 自动发现机制依赖目录结构

### API 限制

- 需要 beta header: `anthropic-beta: skills-2025-10-02`
- 使用 `/v1/skills` 端点

## 五、设计建议

### 平衡艺术

| 维度 | 过左 | 平衡 | 过右 |
|------|------|------|------|
| **描述范围** | 过于狭窄 | 覆盖主要用例 | 过于宽泛 |
| **指令详细度** | 过于简略 | 结构化可操作 | 过于冗长 |
| **文件大小** | 过度拆分 | 合理分块 | 单文件过大 |

### 成功标志

- Skill 在预期场景可靠触发
- Skill 在无关场景保持休眠
- 输出一致且高质量
- 用户无需额外解释即可使用
