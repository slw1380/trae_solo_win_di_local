# Claude Skills 创建指南 - 测试与验证

---

## 测试的重要性

在部署前用真实场景测试 Skill。系统性测试能发现：
- 指令中的缺口
- 描述中的歧义
- 实际使用中才会出现的边界情况

---

## 三大基础测试场景

### 1. 正常操作测试（Normal Operations）

测试 Skill 应该完美处理的典型请求。

**示例：**
- 财务分析 Skill → "analyze Microsoft's latest earnings"
- 数据包 Skill → "build a datapack for this 10-K filing"

**目的**：确认指令按预期工作。

### 2. 边界情况测试（Edge Cases）

测试不完整或异常的输入。

**测试点：**
- 数据缺失时如何处理？
- 文件格式异常时如何处理？
- 用户指令模糊时如何处理？

**预期行为**：优雅降级 - 要么产生降级但仍有用的输出，要么解释需要什么才能继续。

### 3. 越界请求测试（Out-of-Scope Requests）

测试相关但不应触发 Skill 的任务。

**示例：**
- NDA 审查 Skill → 测试 "review this employment agreement"
- NDA 审查 Skill → 测试 "analyze this lease"

**预期行为**：Skill 保持休眠，让其他 Skill 或 Claude 的通用能力处理。

---

## 深度验证测试

### 触发测试（Triggering Tests）

| 测试项 | 说明 |
|--------|------|
| **显式请求** | "use the financial datapack skill to analyze this company" |
| **自然请求** | "help me understand this company's financials" |
| **无关请求** | 测试 Skill 是否保持不激活 |
| **边界请求** | 测试相似但不同的请求，验证边界 |

### 功能测试（Functional Tests）

| 测试项 | 说明 |
|--------|------|
| **输出一致性** | 相似输入是否产生可比较的结果？ |
| **可用性** | 不熟悉该领域的人能否成功使用？ |
| **文档准确性** | 示例是否与实际行为匹配？ |

## 迭代优化

### 监控指标

- **触发一致性** - 描述是否需要优化？
- **输出稳定性** - 指令是否需要澄清？

### 优化原则

> 与 Prompt 一样，最好的 Skill 通过实际应用不断进化。

1. 如果触发不一致 → 优化描述
2. 如果输出变化意外 → 澄清指令
3. 持续监控实际使用表现
