# Claude Code vs Codex CLI 对比分析 - 安全与权限机制

---

## 一、权限系统对比

### 1.1 默认权限策略

| 特性 | Claude Code | Codex CLI |
|------|-------------|-----------|
| **默认模式** | 保守（修改前确认） | 自动（工作目录内） |
| **文件读取** | 需要确认 | 自动 |
| **文件写入** | 需要确认 | 自动（工作目录内） |
| **命令执行** | 需要确认 | 自动（工作目录内） |
| **网络访问** | 需要确认 | 需要确认 |

### 1.2 权限模式详情

**Claude Code 权限模式：**

```bash
# 标准模式（默认）
# - 读取文件：自动
# - 修改文件：请求确认
# - 执行命令：请求确认
# - 网络访问：请求确认

# 自动接受模式
Shift+Tab 切换

# YOLO 模式（危险）
claude --dangerously-skip-permissions

# 细粒度权限控制
/permissions add "Bash(git commit:*)"
/permissions add Edit
```

**Codex CLI 权限模式：**

```bash
# Auto 模式（默认）
# - 工作目录内：自动执行
# - 工作目录外：需要确认
# - 网络访问：需要确认

# Read Only 模式
/approvals  # 切换到只读

# Full Access 模式
/approvals  # 切换到完全访问（谨慎使用）

# 命令行指定
codex --sandbox read-only "分析项目架构"
```

## 二、沙盒机制

### 2.1 沙盒实现

| 特性 | Claude Code | Codex CLI |
|------|-------------|-----------|
| **沙盒类型** | 权限控制系统 | 系统级沙盒 |
| **macOS** | 权限控制 | Apple Seatbelt |
| **Linux** | 权限控制 | Docker 容器 |
| **网络隔离** | 权限控制 | 默认禁用网络 |
| **文件系统隔离** | 工作目录限制 | 沙盒目录限制 |

### 2.2 安全性评估

**Claude Code 安全机制：**
- 细粒度工具权限
- 操作前确认
- Checkpoint 安全回滚
- 本地执行（无云端代码上传）

**Codex CLI 安全机制：**
- 系统级沙盒隔离
- 网络访问控制
- 审计日志
- 本地执行优先

## 五、风险与注意事项

### 5.1 常见风险

| 风险 | Claude Code | Codex CLI |
|------|-------------|-----------|
| **误操作** | Checkpoint 可回滚 | 依赖 Git 回滚 |
| **代码泄露** | 本地执行风险低 | 本地执行风险低 |
| **恶意代码** | 权限控制缓解 | 沙盒隔离缓解 |
| **网络攻击** | 网络权限控制 | 网络隔离 |

### 5.2 安全建议

**通用建议：**
1. 使用版本控制（Git）
2. 定期审查 AI 生成的代码
3. 限制敏感文件访问
4. 使用最小权限原则
5. 启用审计日志

**Claude Code 特定：**
1. 利用 Checkpoint 功能
2. 配置细粒度权限
3. 使用 `/permissions` 管理访问

**Codex CLI 特定：**
1. 使用沙盒模式
2. 谨慎使用 Full Access
3. 定期审查 AGENTS.md
